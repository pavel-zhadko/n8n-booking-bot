# Telegram-бот приёма заявок и онлайн-записи клиентов (n8n)

Система из двух workflow: бот принимает заявки, ведёт их статусы в Google Sheets и записывает клиентов на свободное время с проверкой занятости в Google Calendar. Второй процесс независимо отслеживает изменение статуса в таблице и уведомляет клиента.

Спроектировано и собрано самостоятельно, без курсов. JavaScript для Code-нод написан с помощью ИИ-ассистентов; диагностика, отладка и архитектурные решения — мои.

---

## Что умеет

**Приём заявки — двумя способами**
- текстом в формате «Имя Телефон» с валидацией номера через regex, нормализацией формата и подсказкой при ошибке;
- по кнопке «Отправить мой номер» — Telegram присылает контакт, номер приходит уже валидным.

Оба пути приводятся к единому формату данных, поэтому вся логика ниже по цепочке общая.

**Уведомление администратора** — сообщение с inline-кнопками «Обработана», «Отклонить», «В работе». Нажатие обновляет статус в таблице и перерисовывает исходное сообщение.

**Онлайн-запись в два шага** — по команде `/запись` бот показывает кнопки с датами на неделю вперёд. После выбора даты запрашивает занятость календаря в этом дне, вычитает занятые часы из рабочих и показывает свободные слоты. Выбранный слот создаётся событием в Google Calendar и попадает в отдельный лист таблицы.

**Автоматическое уведомление клиента** — отдельный workflow следит за колонкой «Статус» и пишет клиенту при её изменении, независимо от того, изменил статус бот или человек вручную.

## Архитектура

Система разделена на два workflow осознанно: у них разные типы триггеров — событие Telegram против изменения данных в таблице. Это повышает надёжность, потому что уведомление клиенту сработает при любом способе правки статуса.

### Workflow 1 — приём заявок и запись

Маршрутизация на трёх Switch-нодах, десять конечных сценариев.

```
Telegram Trigger (message, callback_query)
│
└─ Switch: тип входящего
   ├─ Контакт → Code (разбор contact) ─┐
   ├─ Текст   → Code (парсинг, regex) ─┴→ Switch1
   │                                      ├─ Заявка   → Sheets (append) → уведомление админу → ответ клиенту
   │                                      ├─ Ошибка   → сообщение с диагностикой
   │                                      ├─ Команда  → справка + reply-клавиатура
   │                                      └─ Календарь→ Code (кнопки дат) → HTTP Request
   │
   └─ Кнопки → Code (разбор callback_data) → Switch2
                                             ├─ Статус заявки → Sheets (appendOrUpdate по номеру)
                                             │                  → answerCallback → editMessageText
                                             ├─ Выбор дня     → answerCallback → editMessageText
                                             │                  → Google Calendar (занятость)
                                             │                  → Code (расчёт слотов) → HTTP Request
                                             └─ Бронирование  → Google Calendar API (создание события)
                                                                → Sheets (журнал записей)
                                                                → answerCallback → editMessageText
```

У Switch и Switch1 включён fallback-выход: элемент, не совпавший ни с одним условием, не теряется молча.

### Workflow 2 — уведомления о смене статуса

```
Google Sheets Trigger (Row Updated, columnsToWatch: Статус)
  → IF (статус не пустой)
  → Code (текст уведомления по типу статуса)
  → Telegram (отправка клиенту)
```

Chat id клиента берётся из той же строки таблицы, куда он был записан при приёме заявки.

## Технические решения

**Прямые HTTP-запросы вместо встроенных нод.** Отправка сообщения с произвольной inline-клавиатурой в Telegram и создание события в Google Calendar реализованы через HTTP Request с ручным формированием JSON — там, где возможностей готовых нод не хватало. Запрос к Calendar API авторизуется предопределённым OAuth2-креденшелом.

**Динамическое окно запроса к календарю.** Границы выборки событий считаются от выбранной клиентом даты выражениями Luxon с явным указанием таймзоны Europe/Moscow.

**Единый формат данных для разных типов входа.** Текстовая заявка и контакт из Telegram приводятся к одинаковому набору полей, поэтому запись в таблицу, уведомление админу и обработка статусов не дублируются под каждый способ.

**Обновление сообщений вместо отправки новых.** После выбора даты и времени сообщения перерисовываются через `editMessageText` — клавиатура исчезает, повторное нажатие становится невозможным, диалог остаётся коротким.

**Передача данных по цепочке, а не по ссылкам на конкретные ноды.** Ноды, общие для нескольких веток, используют `$json` или ссылку на узел, который выполняется в любой ветке.

## Как запустить у себя

1. Импортировать `workflow_main.json` и `workflow_notifications.json` в n8n (Workflows → Import from File).
2. Создать креденшелы: Telegram API (токен от @BotFather), Google Sheets OAuth2, Google Sheets Trigger OAuth2, Google Calendar OAuth2 — через проект в Google Cloud Console с включёнными Calendar API и Sheets API.
3. В креденшеле Google Calendar включить **Allow use in HTTP Request node** — иначе прямой запрос к Calendar API будет отклонён.
4. Заменить плейсхолдеры на свои значения:
   - `<YOUR_BOT_TOKEN>` — токен бота в URL ноды HTTP Request
   - `<YOUR_SHEET_ID>` — ID Google-таблицы
   - `<YOUR_CALENDAR_ID>` — ID календаря
   - `<YOUR_ADMIN_CHAT_ID>` — chat id администратора
5. Создать таблицу с листами и колонками из раздела выше.
6. В @BotFather задать меню команд: `/setcommands` → `start` и `zapis`.
7. Активировать оба workflow. Google Sheets Trigger работает поллингом и без активации не сработает.

## Отладка: что ломалось и почему

Список проблем, которые пришлось локализовать в процессе — сохранён как справка для тех, кто пойдёт похожим путём.

| Симптом | Причина | Решение |
|---|---|---|
| Команды не работают, ошибок нет | В условиях Switch после `}}` остался перенос строки — результат становился строкой вместо boolean, условие не срабатывало, элемент терялся без fallback-выхода | Убрать перенос, добавить fallback-выход |
| Прямой запрос к Calendar API отклоняется | Креденшел по умолчанию запрещён к использованию в HTTP Request | Включить флаг в настройках креденшела |
| Ветка обрывается после запроса календаря | Нода вернула ноль элементов — n8n молча останавливает выполнение | Always Output Data |
| `Referenced node doesn't exist` | Ссылка на ноду, не выполняющуюся в текущей ветке | Передача данных по цепочке через `$json` |
| Дата съезжает на день назад | `getTimezoneOffset()` на сервере в UTC возвращает 0, а подпись кнопки считалась в московской зоне | Обе величины через Luxon с явной зоной |
| Все действия дублируются | Одновременно активны production-webhook и тестовый прогон — Telegram доставляет событие на оба адреса | Не держать Active и Execute workflow одновременно |
| Статус пишется в чужую строку | Поиск шёл по телефону, не уникальному при повторных заявках | Известное ограничение, решается уникальным ключом заявки |

## Ограничения

- Повторная заявка с того же номера: статус проставляется в первую найденную строку. Решается добавлением уникального идентификатора заявки в `callback_data`.
- Рабочие часы (10:00–18:00) и горизонт записи (7 дней) заданы константами в коде.
- Нет обработки ситуации, когда слот занят между показом клавиатуры и нажатием кнопки.
